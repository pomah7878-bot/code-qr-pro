Product card: public ЧЗ mobile-check from the client browser (works without token)

GitHub research (georgy-komarov/MarkScanner, theYahia/chestnyznak-mcp):
- real endpoint is POST https://mobile.api.crpt.ru/mobile/check with the marking code;
  response has productName, category, status, checkResult, codeResolveData and
  <category>Data (brand, productKind, nominalQuantity, composition, manufacturerName,
  producedDate, expirationDate, serviceLife) — exactly the card gsdmx.ru shows
- our VPS gets HTTP 451 (CRPT blocks datacenter IPs), but the API sends CORS
  access-control-allow-origin for our domain, so we call it from the client's browser

Implementation:
- web/src/lib/cz-public.js: browser fetch as a CORS-simple form POST (no preflight),
  30-min sessionStorage cache, human-readable (01)..(21).. code normalized to machine form,
  Russian status mapping, crypto check flag, huge-response field mapping
- Reprint: «Карточка товара по коду» first asks ЧЗ from the browser, then falls back to
  server (personal ЧЗ token -> Open Food/Beauty Facts -> own history); «В этикетку» fills
  name/brand/manufacturer/size/composition/production date/expiry
- CSP connect-src now allows https://mobile.api.crpt.ru
- server lib/product-card.js: normalizes codes for ЧЗ calls (human-readable -> machine)
