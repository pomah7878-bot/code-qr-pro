# Покупка на юридическое лицо и автоматический счёт

Дата: 21.11.2026.

## Как это работает

1. В разделе **«Подписка»** покупатель выбирает **«Юридическое лицо»**.
2. Заполняет: полное наименование, ИНН, КПП (для ИНН из 10 цифр обязателен), юридический адрес, email для счёта.
3. Нажимает **«Выставить счёт (PDF)»** — заказ создаётся в статусе `pending`, счёт формируется автоматически и открывается в PDF.
4. Оплата — банковским переводом по реквизитам из счёта.
5. После поступления денег администратор в **«Платежи»** нажимает **«Подтвердить»** — тариф активируется, статус заказа меняется на `paid`.
6. Счёт можно скачать повторно из «Истории платежей» (покупатель) и из админки.

Для физических лиц всё по-прежнему: ЮKassa, карта/СБП, подтверждение платежа вебхуком.

## Где заполнить реквизиты продавца

**Админка → Настройки → «Реквизиты для счетов (B2B)»**:

- наименование продавца (ФИО / ИП / ООО);
- налоговый статус (например, «Плательщик налога на профессиональный доход (самозанятый)»);
- ИНН, адрес, телефон, email;
- банк, БИК, расчётный счёт, корреспондентский счёт.

Пока обязательные реквизиты не заполнены, кнопка счёта для юрлиц неактивна, а API возвращает `409 invoice_not_configured`. Это защищает от выпуска неполных счетов.

## Данные и документы

В заказе сохраняются:

- `buyer_type = legal`, `payment_method = bank_transfer`, `provider = invoice`;
- наименование, ИНН, КПП, адрес и email организации;
- номер счёта (`СЧ-ГГГГ-NNNN`) и дата выпуска.

Счёт содержит продавца, покупателя, услугу (тариф и срок), сумму, «Без НДС (НПД)», назначение платежа и подпись. PDF отдаётся по адресу `GET /api/billing/orders/:id/invoice` только владельцу заказа или администратору.

## API

- `GET /api/billing/invoice-info` — доступна ли оплата по счёту и каких реквизитов не хватает.
- `POST /api/billing/checkout` с `buyerType: "legal"` и объектом `buyer` — создаёт заказ и счёт.
- `GET /api/billing/orders/:id/invoice` — PDF счёта.
- `PUT /api/admin/settings` с объектом `invoice` — сохранение реквизитов продавца.
- `POST /api/admin/orders/:id/confirm` — подтверждение банковской оплаты; активирует именно тариф заказа (START/PRO/BUSINESS), а не legacy PREMIUM.

## Что нужно от владельца

Для работы B2B-оплаты нужны **реальные банковские реквизиты самозанятого** и **ФИО**:

- ФИО / наименование продавца;
- ИНН (уже указан: 504706547269);
- банк, БИК, расчётный счёт, корр. счёт;
- адрес и телефон для счёта.

Их можно вписать в админке (Настройки → Реквизиты для счетов) без пересборки сайта.

## Проверка

- Создание заказа юрлица: HTTP 200, счёт `СЧ-2026-0005`, PDF `application/pdf` ~25 КБ (встроенный шрифт Liberation Sans, корректная кириллица).
- Невалидные реквизиты покупателя: HTTP 400 с понятной ошибкой.
- Подтверждение оплаты админом: заказ `paid`, у пользователя активирован именно START (не legacy PREMIUM).
- Мобильная и десктопная формы выбора покупателя: 0 JS-ошибок.
