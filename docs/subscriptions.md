## 2. Семантика лимитов

- **Операция** — обработка одного кода/позиции: генерация кода, этикетка в PDF/печати, подготовка к Print Bridge, расширенная проверка кода (статус).
- **Расширенная проверка** — один успешный внешний запрос за дополнительными сведениями: карточка из каталога по GTIN или статус конкретного кода.
- Учёт раздельный: `usage_periods.ops_used` и `usage_periods.checks_used`, дневные счётчики в `usage_daily`.
- Повторная карточка по тому же GTIN из кэша **не списывает** проверку.
- Неуспешные/сетевые ошибки источника проверку не списывают (пишутся в `external_requests` с `ok=0`).
- Идемпотентность: `usage_events.idem_key` (уникальный индекс) + `generation_jobs.idem_key`. Повторное нажатие с тем же ключом не списывает повторно и не создаёт дубль задания.
- Лимит сбрасывается при начале оплаченного периода (`subscriptions.started_at`), в триале — от даты старта, на FREE — с 1-го числа месяца.
- Дневной лимит FREE (20/день) проверяется отдельно; обновление в 00:00 UTC.

### Как считается цена/период

`plans.price_monthly` / `plans.price_yearly`; при оплате годового периода — 365 дней. Смена тарифа создаёт новый платёж; после подтверждения новый период начинается с текущего момента, старая подписка получает статус `replaced`.

## 3. Пробный период PRO

- 7 календарных дней, один раз на аккаунт (`users.trial_used`), `trial_started_at/trial_ends_at`.
- Доступны все возможности PRO, расширенных проверок — 50 (`app_settings.trial_checks`).
- За 2 дня отправляется уведомление администратору (`trial_notice_at`, `app_settings.trial_notice_days`); в кабинете показывается баннер с датой окончания.
- По окончании автоматически FREE (`startSubscriptionSweeper`, раз в минуту), деньги не списываются.
- Если пользователь оплачивает тариф во время триала — активируется оплаченный период с текущего момента, `trial_used` сохраняется (повторный триал запрещён).

## 4. Оплата

- Провайдер: ЮKassa (`YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`).
- `POST /api/billing/checkout` — покупка/продление/смена тарифа; `period: month|year`.
- `POST /api/billing/check` — проверка заказа по API ЮKassa (fallback).
- `POST /api/billing/webhook/yookassa` — серверное уведомление. Тело не доверяется: платёж запрашивается через API, сверяется сумма и метаданные, повторная обработка блокируется таблицей `payment_events` (PK `external_id`).
- Подписка активируется только после серверного подтверждения (webhook или `checkOrder`), возврат со страницы оплаты сам по себе тариф не включает.
- Автопродление: флаг `subscriptions.auto_renew` + переключатель в кабинете; автосписание провайдером не включено — управление ручное (см. «Ограничения»).
- Возвраты/отмены — через админку платежей и API ЮKassa.

## 5. Расширенная проверка DataMatrix

Серверный модуль `server/src/lib/product-card.js`:

1. `parseDataMatrix()` — локальный разбор GS1 (AI 01/21/10/11/17/91/92/93, контрольная цифра GTIN, даты, структура). Всегда работает, даже без доступа к внешним API.
2. `ProductCatalogAdapter` — карточка по GTIN через публичный mobile API «Честного ЗНАКа» (POST form; с российского IP работает). Кэш по GTIN в `product_cards`.
3. `MarkingStatusAdapter` — статус конкретного кода (без длинного кэша; ошибки кэшируются на 60 с).
4. `CacheService` — TTL карточки `app_settings.cache_card_ttl_seconds` (по умолчанию 86400), ошибки `cache_error_ttl_seconds` (60), защита от одновременных одинаковых запросов (`inflight`).
5. `UsageMeter` — списание операций/проверок, идемпотентность, дневные лимиты.
6. `external_requests` — журнал успехов/ошибок/латентности для админки и статистики стоимости.

Внешние API вызываются **только на сервере**; браузер обращается к `/api/product/cards`. Поля карточки: GTIN, наименование, производитель, бренд, категория, вид, объём, состав, страна, дата изготовления, срок годности, статус, криптозащита, источник, источники, время обновления. Отсутствующие поля отдаются пустыми + список `missing`; фронтенд показывает «Нет данных».

Важно: локальная проверка структуры **не** подтверждает подлинность и нахождение в обороте — это отдельный статус-адаптер.

## 6. Админка

**Админка → Тарифы и подписки** (нужна 2FA):

- «Тарифы» — цены месяц/год, лимиты, форматы, функции, рекомендованный тариф, включение/отключение, создание новых тарифов.
- «Подписки» — поиск клиентов, тариф, период, использование; назначение тарифа вручную, продление, выдача триала, отключение автопродления.
- «Платежи» — все заказы с суммой, статусом и провайдером.
- «Ошибки и статистика» — пользователи по тарифам, платежи за 30 дней, активные триалы, стоимость и ошибки внешних запросов.

Все ручные изменения подписок пишутся в `audit_log` (`billing.plan_assign`, `billing.trial_grant`, `billing.extend`, `billing.cancel_admin` и т.д.).

## 7. База данных

Новые миграции (v29–v35, применяются автоматически при старте):

- `plans` — тарифы;
- `usage_periods`, `usage_events` — периоды и идемпотентные события;
- `usage_daily.ops_used/checks_used` — дневные счётчики;
- поля `users.trial_*`, `trial_notice_at`;
- поля `product_cards` (состав, страна, даты, крипто, источник, TTL);
- `external_requests`, `payment_events`;
- `orders.kind/period/plan_title`, `subscriptions.source/auto_renew/canceled_at/plan_title`;
- `generation_jobs.idem_key` + уникальный индекс.

## 8. Резервное копирование и откат

Перед деплоем обязательно:

```bash
# на сервере, от root
mkdir -p /opt/backups/deploy-$(date +%Y%m%d-%H%M)
cp -a /opt/code-qr/server /opt/backups/deploy-.../server
sqlite3 /opt/code-qr/server/data/app.db ".backup '/opt/backups/deploy-.../app.db'"
```

Восстановление:

```bash
systemctl stop code-qr
cp -a /opt/backups/deploy-.../server /opt/code-qr/server
sqlite3 /opt/code-qr/server/data/app.db ".restore '/opt/backups/deploy-.../app.db'"   # или cp, если WAL нет
chown -R codeqr:codeqr /opt/code-qr/server/data
systemctl start code-qr
```

Откат кода без БД: заменить `/opt/code-qr/server/src` и `/opt/code-qr/web/dist` из бэкапа, перезапустить. Схема БД обратно совместима (новые таблицы/поля не мешают старому коду), откатывать миграции не требуется.

Ежедневные шифрованные бэкапы: `/opt/code-qr/deploy/backup.sh` (cron 03:30), файлы в `/opt/backups/code-qr`.

## 10. Известные ограничения

- Автопродление: согласие хранится и отображается, но фактическое автосписание ЮKassa (сохранённый способ оплаты) не включено — продление ручное; при необходимости реализуется отдельным этапом (save_payment_method + recurring).
- «Сотрудники» — только признак тарифа (`features.employees`), многопользовательские команды не реализованы.
- Официальный True API «Честного ЗНАКа» требует КЭП/токен; публичный mobile API используется как доступный источник карточки/статуса.
- При исчерпании расширенных проверок карточка отдаётся из кэша/локального разбора с предупреждением, лимит операций расходуется отдельно.
