# Защита проекта

## GitHub

Репозиторий **приватный**. Доступ только у владельца; сторонние участники не добавляются.

Включено/добавлено:

- `SECURITY.md` — приватный канал для уязвимостей;
- `CONTRIBUTING.md` — только идеи и поддержка, без кода;
- `LICENSE` — все права защищены, копирование запрещено;
- `CODEOWNERS` — владелец репозитория;
- issue-шаблоны без секретов;
- Dependabot для npm и GitHub Actions;
- GitHub Actions: npm audit, gitleaks, dependency review;
- branch protection: без force-push и удаления `master`.

Рекомендуется в настройках GitHub:

- включить 2FA у владельца;
- включить secret scanning и push protection (если доступно);
- включить Dependabot alerts и security updates;
- ограничить Actions: разрешённые actions, read-only токен по умолчанию;
- не добавлять collaborators без необходимости;
- не публиковать `.env`, ключи, дампы БД и скриншоты с приватными данными.

## Сервер

- `.env` — только на сервере, `chmod 600`, не в Git;
- SSH — ключи, без пароля root, желательно ограничить IP;
- firewall: только 22/80/443, остальное закрыто;
- nginx + HTTPS/HSTS, security headers уже включены;
- админка — 2FA;
- API-ключи хранятся хешами, отзыв при утечке;
- rate-limit на API и формы;
- бэкапы шифруются и хранятся вне сервера;
- логи и мониторинг ошибок/входов;
- обновления зависимостей и ОС.

## Клиентский код

Полностью скрыть JavaScript в браузере невозможно: его можно прочитать в DevTools. Меры:

- исходники не публикуются;
- production-сборка минифицирована, source maps отключены;
- серверные проверки прав и лимитов не дублируются только на клиенте;
- секреты и ключи никогда не попадают в браузер;
- лицензия запрещает копирование и распространение;
- товарный знак и фирменный стиль защищаются отдельно.

## Что делать при инциденте

1. Отозвать API-ключи и сессии.
2. Сменить пароли/2FA владельца.
3. Проверить `audit_log`, `login_events`, `app_logs`.
4. Восстановить БД из проверенного бэкапа при необходимости.
5. Уведомить затронутых пользователей, если есть риск их данным.
